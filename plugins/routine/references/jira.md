# Jira: факты, связи и смысл

Используй TWG-инструкции для Jira и поддерживаемые ими операции. Не зашивай имена полей, типы задач, project key или версию разметки из другого проекта. При записи используй актуальный контракт инструмента и формат тела, который он ожидает; не переносить старые предположения про искажения markdown в любой новый клиент.

## С чем может прийти пользователь

- **Идея без задачи:** намерение задаёт будущий объём; код может отсутствовать, быть частичным или готовым. Найди подходящего родителя в согласованном контексте; существующий код показывает выполненное, но не весь замысел.
- **Существующая задача:** прочитай текущие требования, родителя и эпик; не переписывай по одному названию ветки.
- **Связать текущий код:** сопоставь изменения и требования. Возможны частичное покрытие, дополнительные изменения, противоречие или слишком бедное описание. Уточни существенную разницу, прежде чем менять смысл задачи.

Для новой задачи defaults YAML — старт поиска. Для существующей задачи используй живые связи и фактический тип Jira. Разные Jira-проекты могут обслуживаться одним репозиторием. При переносе ключ может измениться: разреши старую ссылку доступными данными, а не создавай замену недоступной задаче. Одного сходства названия недостаточно для выбора родителя.

Перед созданием ищи дубли по контексту, намерению и имеющимся связям. При неоднозначности предложи кандидатов в чате. Создание родителя допустимо только когда это входит в запрос и подходящего нет; оно не является автоматическим следствием пустой выдачи поиска.

## Оформление

[Шаблон задачи](../templates/jira-task.md) сохраняет три смысловых раздела; [итоговый комментарий](../templates/jira-comment.md) отделяет выполненное от проверенного. Не сокращать критерии готовности до уже реализованного. Не объявлять legacy-задачу обязательной миграцией всего текста: меняй то, что нужно запросу, и сохраняй существенное содержимое.

Если отдельная текущая запись изменена другим участником, перечитай, сопоставь разницу и обнови только согласованные поля. Не меняй автоматически assignee, статус, эпик или родителя ради унификации. Разрешение создать задачу не разрешает переместить существующую в другой проект.

На повторном вызове проверяй существующий результат. Перед добавлением итогового комментария посмотри, не опубликован ли уже тот же результат. Обновлять можно свой однозначно определённый итог при подходящем контракте; чужие комментарии не редактировать. После операции перечитай фактические поля и ссылки. При неизвестном результате записи сначала проверь наличие созданного, а не повторяй её вслепую.
