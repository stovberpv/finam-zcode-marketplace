# Routine · 0.1.0

Плагин ZCode для общей формы Jira-задач, описаний MR и результатов проектного ревью. Два скилла: `routine-init` и `routine-assist`. Разработка кода, коммиты и push остаются у проектных инструментов.

## Требования к среде

До установки пользователь подготавливает:

- ZCode с поддержкой плагинов и открытый рабочий репозиторий.
- Официальный Atlassian MCP, авторизованный на нужном Jira-сайте, с необходимыми правами.
- TWG-скиллы `twg` и `twg-jira` с их рабочей средой исполнения. Версии этих скиллов, использующие CLI `twg`, требуют настроенный CLI; MCP сам по себе его не устанавливает.
- Установленный и авторизованный `glab` для нужного локального GitLab; сетевой доступ, доверие сертификату и права на MR/обсуждения.
- Git и инструменты проекта.

Это формальные предусловия. Плагин не устанавливает интеграции, не запускает health-check их наличия и не добавляет dependency-hooks. Ненастроенную среду исправляет пользователь. Ошибка конкретной операции остаётся ошибкой, а не успешной записью.

## Установка для пилота

1. Открыть целевой репозиторий в ZCode.
2. Settings → Plugins → Create → Add marketplace.
3. Указать `https://github.com/stovberpv/finam-zcode-marketplace.git`. Для локальной установки можно выбрать каталог с `marketplace.json` и `plugins/routine/`; для архива сначала распаковать его и выбрать `finam/`.
4. В Personal найти marketplace **finam**, установить **routine** и оставить включённым.
5. В новом разговоре выбрать `$routine-init` или команду `/routine_init`.

Плагин работает с текущим проектом, не с каталогом marketplace. После обновления исходников обновить marketplace и установленный плагин в интерфейсе; не предполагать горячее обновление существующего чата. Версия marketplace и plugin.json должна совпадать.

## Первый запуск

```text
$routine-init Изучи этот проект. Предложи настройки Routine,
но до моего решения не создавай и не переписывай правила.
```

Агент покажет найденное и предложит для каждого артефакта: создать / дополнить, структурировать или оставить. Ревью выбирается отдельно. После согласования появляется `.harness/workflow/project.yaml` со ссылками на правила, командами и исполнителем ревью. Существующие документы могут остаться на своих местах.

## Работа

```text
$routine-assist Свяжи текущие изменения с задачей, которую мы обсуждали,
и подготовь описание MR. Пока ничего не публикуй.
```

```text
$routine-assist Проведи проектное ревью текущего MR и покажи результат.
```

```text
$routine-assist Опубликуй согласованное описание и замечания в этот MR.
```

Альтернативный короткий вход — `/routine <запрос>`. Имена скиллов и команд выбираются в меню ZCode; если клиент отображает namespace плагина, использовать показанный им вариант.

## Статус проверки

Пакет предназначен для первого пилота. Структурная проверка и изолированные сценарии разработки не заменяют загрузку в конкретную версию ZCode и реальные операции Jira / GitLab. Инструкцию пилота и результаты проверок см. рядом с поставкой; автоматической установки в проекты нет.
