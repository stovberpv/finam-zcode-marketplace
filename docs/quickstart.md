# Routine: инструкция для первого запуска

Routine помогает одинаково оформлять задачи Jira, описания MR и результаты проектного ревью в разных проектах.

## Установка

1. Откройте свой рабочий проект в ZCode.
2. **Settings → Plugins → Create → Add marketplace**. Вставьте:

   ```text
   https://github.com/stovberpv/finam-zcode-marketplace.git
   ```

3. В **Personal → finam** установите **routine**.

Для работы должны быть настроены официальный Atlassian MCP, скиллы TWG (`twg`, `twg-jira`) с нужной им средой и `glab`, авторизованный в вашем GitLab. Подробности — в [требованиях плагина](../plugins/routine/README.md#требования-к-среде).

## Один раз для проекта

```text
/routine_init Изучи проект и предложи настройку Routine. Покажи, какие правила, проверки и ревью уже есть. Перед созданием или изменением правил согласуй со мной план.
```

Обсудите предложения агента и согласуйте нужные изменения. Результат — `.harness/routine/project.yaml`: настройки Jira/GitLab, ссылки на правила, проверки и способ вызова проектного ревью. Если адрес эпика нельзя найти в контексте, укажите его при настройке; переносить его в каждый следующий запрос не нужно.

## Повседневная работа — выберите подходящий пример

**Код уже написан, задачи ещё нет:**

```text
/routine Посмотри изменения текущей ветки. Создай для этой работы задачу Jira и draft MR по нашим шаблонам. Если задача или MR уже есть — используй их. Неясные цель, родителя или целевую ветку уточни у меня.
```

**Задача уже есть:** замените `PROJ-123` на ключ своей задачи, либо сошлитесь на задачу, которую уже обсуждали в чате.

```text
/routine Свяжи текущие изменения с PROJ-123. Проверь описание задачи и подготовь описание MR по шаблону. Пока ничего не публикуй.
```

**Нужно ревью:**

```text
/routine Проведи проектное ревью текущего MR и покажи отчёт по нашему шаблону. Пока не публикуй комментарии.
```

**После проверки подготовленного текста:**

```text
/routine Опубликуй согласованное описание и подтверждённые замечания в этот MR.
```

Команды выполняются в чате ZCode, не в терминале. Если ZCode показывает имя с префиксом плагина, выберите соответствующую команду из меню. Альтернативные входы — скиллы `routine-init` и `routine-assist`.

Routine не делает коммиты и push: перед созданием MR ветка должна быть отправлена в GitLab вашими обычными инструментами. Если проектный исполнитель ревью не настроен, агент сообщит, что ревью не проводилось. Это альфа: при первом запуске проверьте созданные документы и реальные записи Jira/GitLab.
